# Integrations: แจ้งเตือนและเชื่อมต่อภายนอก

Integration ใน Raina ช่วยเปิดประตูให้ระบบ IoT ของคุณสื่อสารออกไปยังโลกภายนอกได้อย่างสะดวก คุณสามารถตั้งค่าการเชื่อมต่อไปยังบริการแจ้งเตือนต่าง ๆ เก็บไว้ล่วงหน้าเพียงครั้งเดียว จากนั้นก็นำชื่อ Integration นั้นไปเรียกใช้ซ้ำในบล็อกคำสั่งของ Automation ได้ทันที ข้อมูลที่เป็นความลับ เช่น API Key หรือ Webhook URL จะได้รับการเข้ารหัสก่อนบันทึก และจะแสดงผลแบบซ่อนไว้บนหน้าจอเพื่อความปลอดภัย

## ช่องทางเชื่อมต่อที่รองรับ (8 ชนิด)

| ช่องทาง | ลักษณะการใช้งาน | ข้อมูลที่ต้องเตรียม |
| :--- | :--- | :--- |
| HTTP service | ยิง Webhook หรือเรียก API ทั่วไป (รองรับเมธอด POST, GET, PUT, PATCH, DELETE) พร้อมรองรับการแนบลายเซ็น HMAC | URL, HTTP Method, Template ของ Header/Body (ถ้ามี) และ Signing Secret (หากต้องการเข้ารหัสลายเซ็น) |
| Telegram | ส่งข้อความเตือนเข้าห้องแชตหรือกลุ่มผ่านบอท | Bot Token (ขอรับได้จาก @BotFather), Chat ID และข้อความที่ต้องการส่ง |
| Slack | โพสต์ข้อความแจ้งเตือนลงช่องสนทนา | Incoming Webhook URL และข้อความ |
| Discord | ส่งข้อความเข้าเซิร์ฟเวอร์ (รองรับทั้งข้อความธรรมดาและ Embed) | Channel Webhook URL, ข้อความ และหัวเรื่อง |
| Email | ส่งอีเมลแจ้งเตือนผ่านบริการ Resend | Resend API Key, อีเมลผู้ส่ง (ต้องยืนยันโดเมนใน Resend แล้ว), อีเมลผู้รับ, หัวข้อ และเนื้อความ |
| Twilio | ส่งข้อความสั้น SMS หรือส่งผ่าน WhatsApp | Account SID, Auth Token, เบอร์โทรผู้ส่ง, เบอร์โทรผู้รับ และข้อความ |
| Microsoft Teams | โพสต์ข้อความแจ้งเตือนลงแชนแนลของทีม | Incoming Webhook URL และข้อความ |
| PagerDuty | เปิด Ticket แจ้งเตือนเหตุการณ์ฉุกเฉิน (Incident) | Routing Key, คำอธิบายสรุปเหตุการณ์, ระดับความรุนแรง (Severity) และ Dedup Key (ถ้ามี) |

## การแทรกตัวแปรลงในข้อความแจ้งเตือน

เพื่อให้ข้อความแจ้งเตือนมีข้อมูลที่แม่นยำและเป็นประโยชน์ต่อผู้รับ คุณสามารถแทรกตัวแปรลงในข้อความได้ เช่น ใส่ `{{variable}}` เพื่อแทนชื่อตัวแปรที่กำลังเกิดปัญหา ใส่ `{{value}}` เพื่อแทนค่าจริง ณ ขณะนั้น หรือใส่ `{{event}}` เพื่อแทนชื่อของอีเวนต์ภายในระบบ

ตัวอย่างเช่น หากคุณพิมพ์ข้อความแจ้งเตือนไว้ว่า `"ตรวจพบค่า {{variable}} สูงผิดปกติที่ {{value}} องศา"` เมื่อระบบทำงานจริงและอุณหภูมิพุ่งไปถึง 38.5 องศา ข้อความที่ส่งไปยังปลายทางก็จะกลายเป็น `"ตรวจพบค่า temperature สูงผิดปกติที่ 38.5 องศา"` โดยอัตโนมัติ

## ขั้นตอนการตั้งค่าและทดสอบ

การเพิ่มช่องทางเชื่อมต่อสามารถทำได้จากหน้า **Automations** หรือเข้าไปที่ส่วน Integrations ในเมนูหลักของโปรเจกต์ จากนั้นกดปุ่มสร้าง เลือกบริการที่ต้องการใช้งาน และกรอกข้อมูลตามที่ระบบกำหนด

จุดสำคัญที่ควรทำทุกครั้งก่อนนำไปผูกเข้ากับเวิร์กโฟลว์จริง คือการกดปุ่ม **Test** ระบบจะยิงข้อความตัวอย่างออกไปยังบริการปลายทางทันที เพื่อให้คุณตรวจเช็กได้ว่า Bot Token หรือ Webhook URL ที่ใส่ไว้ทำงานได้จริง เมื่อยืนยันว่าข้อความเข้าเรียบร้อยแล้ว คุณจึงค่อยเปิดเข้าไปที่หน้าแก้ไข Automation เพื่อเพิ่มบล็อก **Integration** แล้วเลือกชื่อช่องทางนี้มาใช้งาน

## การดูแลรักษาและความปลอดภัยของข้อมูล

หากคุณต้องการพักการส่งแจ้งเตือนของช่องทางใดชั่วคราว คุณสามารถปิดสวิตช์ Enabled ของ Integration นั้นได้ทันทีโดยไม่ต้องลบข้อมูลทิ้ง เมื่อพร้อมใช้งานใหม่ก็เพียงแค่เปิดสวิตช์กลับมา

เมื่อคุณเปิดเข้ามาแก้ไขรายละเอียด ข้อมูลที่เป็นความลับจะแสดงในรูปแบบจุดไข่ปลา `••••` เสมอ ซึ่งระบบจะไม่เขียนข้อมูลทับหากคุณไม่ได้แตะต้องช่องนั้น คุณจึงสามารถแก้ไขข้อความหรือชื่อเรียกได้โดยไม่ต้องคอยพิมพ์รหัส Token ซ้ำทุกครั้ง นอกจากนี้ คุณยังสามารถดูสถานะการยิงข้อมูลรอบล่าสุดได้จากหน้ารายการ Integration ซึ่งจะแสดงให้เห็นชัดเจนว่าส่งสำเร็จเป็น `ok` หรือเกิด `error` พร้อมทั้งแสดงข้อความตอบกลับจากเซิร์ฟเวอร์ปลายทางเพื่อช่วยในการวิเคราะห์ปัญหา

หากต้องการดูตัวอย่างการนำ Integration ไปสร้างเป็นระบบแจ้งเตือนเตือนภัยจริง สามารถดูต่อได้ใน [Tutorial ครบวงจร](./tutorials.md)
