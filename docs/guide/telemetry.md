# ส่งข้อมูล telemetry (HTTP)

การส่งข้อมูล Telemetry ผ่าน HTTP POST เป็นวิธีที่สะดวกและตรงไปตรงมาที่สุด เหมาะสำหรับสคริปต์อัตโนมัติบนเซิร์ฟเวอร์ เกตเวย์รับส่งข้อมูล อุปกรณ์แบบใส่ซิมที่ตื่นขึ้นมาส่งข้อมูลเป็นช่วงเวลา หรืออุปกรณ์ขนาดเล็กที่ไม่จำเป็นต้องเปิดคอนเนกชันค้างไว้ตลอดเวลา

> หากคุณใช้งานบอร์ดไมโครคอนโทรลเลอร์อย่าง ESP32 หรือ Arduino และต้องการให้บอร์ดรักษาการเชื่อมต่อไว้ตลอดเวลาเพื่อรอรับคำสั่งควบคุมแบบทันที แนะนำให้ใช้โปรโตคอล [RLP และเฟิร์มแวร์](./rlp-and-firmware.md) แทน

## Endpoint และการยืนยันตัวตน

ในการส่งข้อมูล ให้ยิง HTTP POST ไปที่ Endpoint `http://<host>:3001/v1/telemetry` หรือหากติดตั้งผ่าน Reverse Proxy พร้อมกับโดเมน ให้เรียกผ่าน `https://<domain>/v1/telemetry`

การยืนยันตัวตนทำได้โดยการแนบ Hardware Token ประจำโปรเจกต์มาใน Header `x-device-token: YOUR_HARDWARE_TOKEN` นอกจากนี้ระบบยังรองรับการส่งผ่าน Header มาตรฐานอย่าง `Authorization: Bearer <token>` หรือจะส่งเป็น query parameter ในรูปแบบ `?token=<token>` ท้าย URL ก็ได้เช่นกัน ทั้งนี้ขนาดของ Payload รวมทั้ง Request ต้องไม่เกิน 64 KB

## รูปแบบข้อมูลและตัวอย่างการส่ง

คุณสามารถส่งข้อมูลในรูปแบบ JSON พื้นฐานได้ทันทีผ่าน cURL:

```bash
curl -X POST http://<host>:3001/v1/telemetry \
  -H "Content-Type: application/json" \
  -H "x-device-token: YOUR_HARDWARE_TOKEN" \
  -d '{
    "deviceId": "esp32_sensor",
    "metrics": { "temperature": 28.5, "humidity": 65.2 }
  }'
```

โครงสร้าง JSON ที่ Raina รองรับมีฟิลด์หลักดังนี้

| ฟิลด์ | รายละเอียดการใช้งาน |
| :--- | :--- |
| `deviceId` (หรือ `device_id`) | ชื่อระบุตัวตนของอุปกรณ์ หากเว้นว่างไว้ ระบบจะผูกข้อมูลเข้ากับ Device เริ่มต้นของ Project |
| `metrics` (หรือใส่ชื่อตัวแปรตรง ๆ) | ข้อมูลคู่ Key-Value ระบุชื่อตัวแปรและค่าที่ต้องการส่ง |
| `ts` (หรือ `timestamp`) | เวลาของข้อมูล (รองรับทั้งหน่วยมิลลิวินาทีและวินาที) หากไม่ระบุ ระบบจะใช้เวลาฝั่งเซิร์ฟเวอร์ขณะรับข้อมูล |

เมื่อเซิร์ฟเวอร์ประมวลผลสำเร็จ จะตอบกลับด้วยรหัส `200 OK` พร้อมรายละเอียดว่าผูกเข้ากับอุปกรณ์รหัสใดและบันทึกไปกี่ตัวแปร:

```json
{ "ok": true, "deviceId": "dev_...", "processed": 2 }
```

## ข้อกำหนดของข้อมูลก่อนส่งเข้าระบบ

เพื่อให้ระบบจัดเก็บข้อมูลได้อย่างถูกต้องและมีประสิทธิภาพ มีข้อกำหนดสำคัญที่คุณควรทราบก่อนออกแบบ Payload

ชื่อตัวแปรจะต้องประกอบด้วยตัวอักษรภาษาอังกฤษ ตัวเลข หรือเครื่องหมาย `a-z A-Z 0-9 _ . -` และมีความยาวไม่เกิน 64 ตัวอักษร หากมีตัวแปรใดใน Request ที่สะกดผิดรูปแบบ Raina จะข้ามเฉพาะตัวแปรนั้นไปเงียบ ๆ โดยไม่ทำให้ตัวแปรอื่นที่ถูกต้องใน Request เดียวกันล้มเหลว

ในหนึ่ง Request คุณสามารถส่งตัวแปรได้สูงสุด 50 ตัวแปร หากส่งเกินกว่านี้ ข้อมูลส่วนเกินจะถูกตัดทิ้ง และค่าของแต่ละตัวแปรจะต้องมีความยาวไม่เกิน 512 ไบต์ โดยต้องเป็นค่าเดี่ยว (Primitive Value) เช่น ตัวเลข ข้อความ หรือบูลีน หากส่ง Object ซ้อนเข้ามา ระบบจะไม่บันทึกค่านั้น

ประเภทของข้อมูลมีผลโดยตรงต่อการแสดงผล หากส่งเป็นตัวเลข เช่น `28.5` ระบบจะบันทึกทั้งสถานะล่าสุดและประวัติย้อนหลังลงฐานข้อมูล Time-Series เพื่อนำไปพล็อตเป็นกราฟ แต่หากส่งเป็นข้อความหรือบูลีน ระบบจะเก็บไว้เฉพาะค่าล่าสุด ซึ่งยังคงนำไปแสดงผลบนการ์ด Value หรือนำไปใช้ในเงื่อนไขของ Automation ได้ตามปกติ เพียงแต่จะไม่สามารถวาดเป็นกราฟเส้นย้อนหลังได้

สำหรับเรื่องเวลา หากคุณแนบฟิลด์ `ts` มาด้วย ค่านั้นจะต้องอยู่ในช่วงเวลาย้อนหลังไม่เกิน 24 ชั่วโมง และล่วงหน้าไม่เกิน 10 นาทีเมื่อเทียบกับนาฬิกาของเซิร์ฟเวอร์ หากอยู่นอกช่วงเวลาดังกล่าว Raina จะบันทึกทับด้วยเวลาปัจจุบันของเซิร์ฟเวอร์แทน เพื่อป้องกันไม่ให้ข้อมูลที่เวลาเพี้ยนไปรบกวนลำดับในฐานข้อมูล

## การดึงข้อมูลประวัติย้อนหลังผ่าน API

โดยทั่วไป Widget ประเภท Chart บนหน้า Dashboard จะทำหน้าที่ดึงข้อมูลประวัติย้อนหลังมาแสดงผลให้คุณเอง แต่หากต้องการดึงข้อมูลดิบไปใช้งานต่อในระบบอื่น คุณสามารถเรียกผ่าน History API ได้โดยตรง โดยต้องยืนยันตัวตนด้วยบัญชีผู้ใช้ที่มีสิทธิ์ในโปรเจกต์:

```text
GET /v1/projects/<project-id>/telemetry/history?variable=temperature&limit=100
```

คุณสามารถส่งพารามิเตอร์เสริมเพื่อกรองข้อมูลให้เจาะจงขึ้นได้ เช่น ใส่ `deviceId` เพื่อเลือกเฉพาะอุปกรณ์ที่ต้องการ กำหนดช่วงเวลาด้วย `from` และ `to` ในหน่วยมิลลิวินาที หรือจำกัดจำนวนข้อมูลที่ต้องการดึงผ่าน `limit` ซึ่งสามารถขอได้สูงสุด 1,000 รายการต่อครั้ง

## การสั่งการอุปกรณ์ (Control)

หากต้องการส่งคำสั่งจากภายนอกกลับไปยังอุปกรณ์ การเรียก API เส้นนี้จะต้องทำผ่านเซสชันของผู้ใช้งานที่ล็อกอินแล้วเท่านั้น โดยไม่สามารถใช้ Hardware Token ยิงคำสั่งได้:

```bash
curl -X POST http://<host>:3001/v1/control \
  -H "Content-Type: application/json" \
  -H "x-session-token: <user-session>" \
  -d '{
    "projectId": "proj_...",
    "deviceId": "dev_...",
    "variableKey": "pump_relay",
    "value": true
  }'
```

ในชีวิตจริงคุณแทบไม่จำเป็นต้องยิงคำสั่งนี้ด้วยตัวเอง เพราะ Widget ในกลุ่ม Control บนหน้า Dashboard จะจัดการเบื้องหลังให้ทั้งหมด เมื่อมีผู้ใช้กดสวิตช์บนหน้าจอ Raina จะอัปเดตสถานะล่าสุดของตัวแปรลงฐานข้อมูลทันที จากนั้นจะส่งคำสั่งควบคุมลงไปยังอุปกรณ์ที่เปิดคอนเนกชัน RLP รออยู่ และอัปเดตสถานะของ Widget บนทุกหน้าจอ Dashboard ที่เปิดดูอยู่ไปพร้อมกัน ทั้งนี้ผู้ใช้ที่กดสั่งงานจะต้องมีสิทธิ์ `canControl` ใน Dashboard หน้านั้นด้วย

หากต้องการดูรายละเอียดเรื่องการเขียนเฟิร์มแวร์เพื่อรับคำสั่งเหล่านี้ สามารถอ่านต่อได้ที่ [RLP และเฟิร์มแวร์](./rlp-and-firmware.md) หรือดูวิธีวางปุ่มสั่งงานบนหน้าจอได้ใน [Dashboards](./dashboards.md)
