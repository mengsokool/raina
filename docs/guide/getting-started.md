# Getting started: จากระบบเปล่าถึง IoT ตัวแรก

คู่มือหน้านี้จะพาคุณเริ่มตั้งแต่การติดตั้ง Raina บนเครื่องเปล่า จนถึงจุดที่คุณเห็นข้อมูลจากอุปกรณ์แรกแสดงผลบน Dashboard แบบเรียลไทม์ เราจะเริ่มต้นจากการรันระบบผ่าน Docker จากนั้นสร้างบัญชีผู้ดูแลคนแรก สร้างพื้นที่โปรเจกต์ และออกกุญแจยืนยันตัวตนให้อุปกรณ์ เมื่อทุกอย่างพร้อม เราจะทดลองส่งข้อมูลจำลองผ่านคำสั่ง cURL และสร้างหน้าจอ Dashboard ขึ้นมาแสดงผลข้อมูลนั้น

> หากคุณยังไม่คุ้นเคยกับคำศัพท์เฉพาะของ Raina เช่น Project, Token หรือ Variable สามารถอ่าน [Concepts](./concepts.md) ควบคู่ไปด้วยได้

## 1. ติดตั้งและเปิดใช้งาน Raina

เส้นทางที่ง่ายและเร็วที่สุดสำหรับการทดสอบคือการรันผ่าน Docker Compose หากต้องการดูรายละเอียดการปรับแต่งสภาพแวดล้อมเชิงลึก สามารถดูเพิ่มเติมได้ที่ [Deploy และดูแลระบบ](./operations.md)

เริ่มต้นด้วยการดึงซอร์สโค้ดและสั่งรันคอนเทนเนอร์ในโหมดเบื้องหลัง:

```bash
git clone https://github.com/mengsokool/raina.git
cd raina
docker compose up -d
```

เมื่อทุกคอนเทนเนอร์เริ่มทำงานเรียบร้อยแล้ว ให้เปิดเว็บเบราว์เซอร์ไปที่ `http://<host>:3000` เพื่อเข้าสู่หน้าเว็บหลักของ Raina ส่วนตัว API เซิร์ฟเวอร์จะทำงานอยู่ที่พอร์ต 3001 ซึ่งเป็นพอร์ตที่ระบบและอุปกรณ์ใช้คุยกัน คุณไม่จำเป็นต้องเปิดเข้าหน้านั้นโดยตรง

## 2. สร้างบัญชีเจ้าของระบบ (Owner)

เมื่อคุณเปิดหน้าเว็บขึ้นมาเป็นครั้งแรก ระบบที่ยังไม่มีผู้ใช้งานจะพาคุณเข้าสู่หน้าลงทะเบียนบัญชี Owner ทันที บัญชีแรกนี้ถือเป็นผู้มีสิทธิ์สูงสุดในการดูแลระบบทั้งหมด ให้กำหนดชื่อผู้ใช้และรหัสผ่านที่มีความยาวอย่างน้อย 8 ตัวอักษร จากนั้นล็อกอินเข้าสู่ระบบ

## 3. สร้าง Project แรก

ใน Raina ข้อมูลอุปกรณ์ ตัวแปร และหน้าจอแสดงผลจะถูกจัดกลุ่มแยกกันตามโปรเจกต์เพื่อความเป็นระเบียบ ให้คลิกไปที่เมนู **Projects** แล้วกดสร้างโปรเจกต์ใหม่ เช่น ตั้งชื่อว่า `Greenhouse A` เมื่อสร้างเสร็จแล้วให้คลิกเข้าไปยังโปรเจกต์นั้น ซึ่ง URL ในแถบที่อยู่จะเปลี่ยนเป็นรูปแบบ `/p/<project-id>/...`

## 4. ออก Hardware Token สำหรับอุปกรณ์

ก่อนที่อุปกรณ์จะเริ่มส่งข้อมูลเข้ามาได้ ตัวอุปกรณ์จำเป็นต้องมี Token ประจำโปรเจกต์สำหรับใช้ยืนยันตัวตน

ให้เข้าไปที่หน้า **Devices** ในโปรเจกต์ที่คุณเพิ่งสร้างขึ้นมา จากนั้นกดปุ่ม **New token** แล้วตั้งชื่อกำกับไว้เพื่อความจำ เช่น `greenhouse-token` เมื่อกดยืนยันแล้ว ให้คัดลอกสตริง Token ที่ปรากฏขึ้นมาเก็บไว้ทันที เพราะระบบจะแสดงค่าจริงของ Token นี้เพียงครั้งเดียวเท่านั้น หลังจากปิดหน้าต่างนี้ไป คุณจะไม่สามารถกลับมาดูค่าเดิมได้อีก

## 5. ส่งข้อมูลครั้งแรก (ไม่จำเป็นต้องมีฮาร์ดแวร์จริง)

คุณสามารถทดสอบส่งข้อมูลเข้าสู่ระบบได้ทันทีโดยไม่ต้องรอต่อสายบอร์ดจริง เพียงเปิด Terminal บนคอมพิวเตอร์แล้วใช้คำสั่ง cURL ยิง HTTP POST เข้าไปยัง API เพื่อจำลองว่ามีอุปกรณ์ชื่อ `demo_esp32` กำลังส่งค่าอุณหภูมิและความชื้นเข้ามา:

```bash
curl -X POST http://<host>:3001/v1/telemetry \
  -H "Content-Type: application/json" \
  -H "x-device-token: YOUR_HARDWARE_TOKEN" \
  -d '{
    "deviceId": "demo_esp32",
    "metrics": { "temperature": 28.5, "humidity": 65.2 }
  }'
```

อย่าลืมเปลี่ยน `YOUR_HARDWARE_TOKEN` ให้เป็นค่าที่คุณเพิ่งคัดลอกมา เมื่อระบบประมวลผลข้อมูลเรียบร้อย เซิร์ฟเวอร์จะส่งคำตอบกลับมาในลักษณะนี้:

```json
{ "ok": true, "deviceId": "dev_...", "processed": 2 }
```

เพียงคำสั่งเดียวนี้ Raina จะจัดการสร้าง Device ชื่อ `demo_esp32` ให้อัตโนมัติ พร้อมทั้งสร้างตัวแปร `temperature` และ `humidity` บันทึกค่าล่าสุดและจัดเก็บประวัติ Time-Series ไว้ในฐานข้อมูลเรียบร้อยแล้ว หากสนใจรายละเอียดเรื่องรูปแบบข้อมูลและข้อจำกัดต่าง ๆ สามารถศึกษาต่อได้ในหน้ารายละเอียดของ [ส่งข้อมูล telemetry](./telemetry.md)

ในกรณีที่คุณอยากเห็นข้อมูลไหลเข้ามาอย่างต่อเนื่องเหมือนมีเซ็นเซอร์ทำงานอยู่จริง คุณสามารถรันสคริปต์จำลองอุปกรณ์ RLP ที่เราเตรียมไว้ให้ในโค้ด โดยดูรายละเอียดเพิ่มเติมได้ที่ [RLP และเฟิร์มแวร์](./rlp-and-firmware.md):

```bash
PROJECT_TOKEN=YOUR_HARDWARE_TOKEN DEVICE_ID=demo_esp32 pnpm emulate
```

## 6. สร้าง Dashboard แรก

เมื่อมีข้อมูลบันทึกอยู่ในระบบแล้ว ขั้นต่อไปคือการนำข้อมูลนั้นขึ้นมาแสดงบนหน้าจอ

ให้เปิดไปที่แท็บ **Dashboards** ภายในโปรเจกต์เดิม แล้วกดสร้าง Dashboard ใหม่ เมื่อเปิดเข้าสู่หน้าแก้ไข ให้ลองลาก Widget ชนิด **Value** มาวางลงบนกริด แล้วตั้งค่าในแผงด้านข้างให้ผูกเข้ากับตัวแปร `temperature` จากนั้นลาก Widget ชนิด **Chart** มาวางเพิ่มอีกตัวเพื่อผูกเข้ากับทั้ง `temperature` และ `humidity`

เมื่อจัดวางเรียบร้อยแล้ว ให้สลับไปยังมุมมองปกติ (View) คุณจะเห็นตัวเลขและกราฟแสดงค่าล่าสุดทันที และหากมีข้อมูลใหม่ส่งเข้ามา หน้าจอนี้ก็จะขยับอัปเดตเองโดยอัตโนมัติ

## 7. แชร์ Dashboard ให้ผู้อื่นดู

หากต้องการส่งหน้าจอนี้ให้เพื่อนร่วมทีมหรือลูกค้าดูโดยที่พวกเขาไม่ต้องมีบัญชีผู้ใช้ในระบบ คุณสามารถกดปุ่ม **Share** ที่มุมบนของ Dashboard แล้วเลือกโหมด **Public access** ระบบจะสร้างลิงก์สำหรับเปิดดูสาธารณะในรูปแบบ `/public/d/<token>` ซึ่งคุณสามารถคัดลอกส่งต่อให้ใครก็ได้เปิดดูได้ทันที และหากต้องการปิดการเข้าถึงในภายหลัง ก็เพียงแค่เปลี่ยนสถานะกลับเป็น Restricted หรือเลือก Paused เพื่อพักการใช้งานชั่วคราว

## สิ่งที่ทำต่อได้จากจุดนี้

เมื่อผ่านขั้นตอนนี้ แสดงว่าระบบพื้นฐานของคุณพร้อมใช้งานแล้ว ต่อจากนี้คุณสามารถขยับไปทำสิ่งต่าง ๆ เพิ่มเติมได้ตามเป้าหมายของงาน:

หากคุณมีบอร์ดจริง เช่น ESP32 หรือ Arduino ให้ศึกษาการต่อสายและลงเฟิร์มแวร์ใน [RLP และเฟิร์มแวร์](./rlp-and-firmware.md)

ถ้าต้องการควบคุมอุปกรณ์กลับจากหน้าจอ เช่น กดเปิดปิดไฟหรือสั่งงานรีเลย์ ให้ดูการใช้งาน Widget กลุ่ม Control ใน [Dashboards](./dashboards.md)

หากต้องการตั้งระบบเฝ้าระวัง เช่น เมื่ออุณหภูมิสูงเกินกำหนดให้ส่งไลน์หรือส่งข้อความเข้ากลุ่ม Telegram ให้อ่านต่อใน [Automations](./automations.md) ควบคู่กับ [Integrations](./integrations.md)

และเมื่อพร้อมจะนำระบบขึ้นรันจริงบนเซิร์ฟเวอร์ ให้ตรวจสอบการตั้งค่าความปลอดภัยและการสำรองข้อมูลใน [Deploy และดูแลระบบ](./operations.md)

นอกจากนี้ คุณยังสามารถทำความเข้าใจโครงสร้างเบื้องหลังเพิ่มเติมได้ที่ [Concepts](./concepts.md) หรือจะลองทำเวิร์กช็อปแบบครบวงจรตั้งแต่ต้นจนจบใน [Tutorial ครบวงจร](./tutorials.md) ก็ได้เช่นกัน
