# Devices และ hardware token

ใน Raina คุณไม่จำเป็นต้องมานั่งกรอกฟอร์มลงทะเบียนอุปกรณ์ทีละตัวล่วงหน้า ทันทีที่อุปกรณ์ส่งข้อมูลชุดแรกเข้ามาพร้อมระบุชื่อและ Token ที่ถูกต้อง ระบบจะสร้างและผูก Device ตัวนั้นเข้ากับ Project ให้โดยอัตโนมัติ

## แนวคิดการลงทะเบียนอุปกรณ์อัตโนมัติ

เมื่ออุปกรณ์ส่งข้อมูล Telemetry เข้ามาเป็นครั้งแรกพร้อมระบุตัวตนผ่านฟิลด์ `deviceId` Raina จะบันทึกอุปกรณ์ใหม่เข้าสู่ Project ของ Token นั้นทันที และจะเริ่มปรากฏให้เห็นในหน้ารายการอุปกรณ์ของ Project

> ข้อควรระวังด้านความปลอดภัย: หากชื่อ `deviceId` นั้นถูกส่งเข้ามาและผูกเข้ากับ Token ตัวหนึ่งไปแล้ว Token อื่นจะไม่สามารถใช้ชื่ออุปกรณ์ซ้ำกันได้ หากมีการส่งเข้ามา ระบบจะปฏิเสธคำขอด้วยรหัสสถานะ `403 Forbidden` พร้อมข้อความ `Device ownership conflict` เพื่อป้องกันไม่ให้อุปกรณ์อื่นมาส่งข้อมูลทับ ดังนั้นคุณควรตั้งชื่ออุปกรณ์ให้สื่อความหมายและไม่ซ้ำกันภายในโปรเจกต์เดียวกัน

หน้า **Devices** ทำหน้าที่เป็นศูนย์กลางสำหรับตรวจสอบอุปกรณ์และจัดการกุญแจเชื่อมต่อทั้งหมดของโปรเจกต์

ในส่วนบนของหน้าจอ คุณสามารถกดปุ่ม **New token** เพื่อออกรหัสใหม่ให้อุปกรณ์นำไปใช้งาน ค่า Token จริงจะแสดงให้เห็นเพียงครั้งเดียวตอนสร้าง คุณจึงต้องจดหรือคัดลอกเก็บไว้ทันที และหาก Token ใดรั่วไหลหรือเลิกใช้งานแล้ว คุณสามารถกดปุ่ม **Revoke** เพื่อเพิกถอน Token นั้นได้ทันที ซึ่งจะส่งผลให้อุปกรณ์ทั้งหมดที่ใช้ Token ดังกล่าวไม่สามารถส่งข้อมูลหรือเชื่อมต่อเข้ามาได้อีก

ถัดลงมาคือรายการอุปกรณ์ที่เคยส่งข้อมูลเข้ามาในโปรเจกต์ ระบบจะแสดงสถานะ Online หรือ Offline โดยพิจารณาจากเวลาที่มีการส่งข้อมูลล่าสุด (`lastSeen`) อุปกรณ์ที่มีการส่งข้อมูลเข้ามาภายในช่วงเวลาประมาณ 5 นาทีล่าสุดจะถือว่ากำลังออนไลน์อยู่ นอกจากนี้ คุณยังสามารถคลิกเข้าไปเปลี่ยนชื่อเรียกของอุปกรณ์ หรือกดปุ่ม Forget เพื่อลบอุปกรณ์ที่ไม่ใช้งานแล้วออกจากระบบได้จากหน้านี้

## กฎการตั้งชื่ออุปกรณ์และตัวแปร

ชื่ออุปกรณ์และชื่อตัวแปรใน Raina ใช้กฎชุดเดียวกันเพื่อความสม่ำเสมอ โดยระบบอนุญาตให้ใช้เฉพาะตัวอักษรภาษาอังกฤษ ตัวเลข รวมถึงเครื่องหมายขีดล่าง ขีดกลาง และจุด (`a-z A-Z 0-9 _ . -`) และจำกัดความยาวไว้ไม่เกิน 64 ตัวอักษร

ตัวอย่างชื่อที่เหมาะสมและสื่อความหมายได้ดี เช่น `greenhouse-01`, `pump_relay` หรือ `soil.moisture` ในขณะที่ชื่อที่มีช่องว่างเว้นวรรค หรือมีอักขระพิเศษอย่างเครื่องหมายทับ เครื่องหมายดอกจัน หรือสัญลักษณ์ชาร์ป (`/`, `*`, `#`) จะไม่สามารถใช้งานได้ ซึ่งระบบจะปฏิเสธคำขอหรือไม่ก็ตัดอักขระเหล่านั้นทิ้งทันที

## วงจรชีวิตของ Hardware Token

1. สร้าง Token ประจำโปรเจกต์จากหน้า Devices โดย Token ตัวเดียวกันนี้สามารถนำไปแชร์ให้อุปกรณ์หลายตัวภายในโปรเจกต์เดียวกันใช้ร่วมกันได้
2. นำค่า Token ไปใส่ในเฟิร์มแวร์ สคริปต์ หรือคอนฟิกของอุปกรณ์
3. เมื่ออุปกรณ์เริ่มเชื่อมต่อหรือส่งข้อมูลเข้ามาเป็นครั้งแรก ระบบจะบันทึกการเป็นเจ้าของระหว่างชื่ออุปกรณ์นั้นกับ Token โดยอัตโนมัติ
4. หากพบว่า Token เกิดการรั่วไหล ให้สร้าง Token ตัวใหม่ขึ้นมา นำไปอัปเดตลงในอุปกรณ์ทั้งหมดให้เรียบร้อย แล้วจึงกดปุ่ม Revoke เพื่อยกเลิก Token เก่าออกจากระบบ

## ส่งข้อมูลจริงเข้าสู่ระบบ

เมื่อเตรียมอุปกรณ์และมี Token พร้อมแล้ว คุณสามารถเลือกช่องทางการส่งข้อมูลได้ตามประเภทของฮาร์ดแวร์

สำหรับสคริปต์อัตโนมัติ คอมพิวเตอร์บอร์ดเดี่ยว เกตเวย์ หรือเซ็นเซอร์ที่ตื่นขึ้นมาส่งข้อมูลเป็นรอบเวลาผ่าน HTTP POST สามารถดูตัวอย่างคำขอและรูปแบบข้อมูลได้ที่ [ส่งข้อมูล telemetry](./telemetry.md)

ส่วนบอร์ดไมโครคอนโทรลเลอร์ เช่น ESP32 หรือ Arduino ที่ต้องการเปิดคอนเนกชันค้างไว้ตลอดเวลาเพื่อส่งข้อมูลและรอรับคำสั่งควบคุมกลับได้แบบทันที ให้ศึกษาการใช้งานผ่านโปรโตคอลเฉพาะของระบบได้ที่ [RLP และเฟิร์มแวร์](./rlp-and-firmware.md)
