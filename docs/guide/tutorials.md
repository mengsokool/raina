# Tutorial: ระบบมอนิเตอร์เรือนกระจกครบวงจร

บทเรียนปฏิบัตินี้จะพาคุณนำฟีเจอร์หลักทั้งหมดของ Raina มาร้อยเรียงเข้าด้วยกัน เริ่มตั้งแต่การสร้างโปรเจกต์ การจำลองเซ็นเซอร์ส่งข้อมูลผ่านโปรโตคอล RLP การออกแบบ Dashboard แสดงผลสด ไปจนถึงการตั้งระบบเฝ้าระวังให้ส่งข้อความแจ้งเตือนเข้า Telegram เมื่อตรวจพบว่าอุณหภูมิร้อนเกินเกณฑ์

กระบวนการทั้งหมดนี้ใช้เวลาทำตามประมาณ 20 นาที และคุณสามารถทำตามได้ทันทีบนคอมพิวเตอร์โดยยังไม่ต้องต่อสายฮาร์ดแวร์จริง สิ่งที่คุณต้องมีก่อนเริ่มคือระบบ Raina ที่ติดตั้งและเปิดใช้งานเรียบร้อยแล้วพร้อมบัญชี Owner รวมถึง Bot Token และ Chat ID ของ Telegram สำหรับรับข้อความแจ้งเตือน (หากยังไม่สะดวกเตรียมบอท สามารถข้ามขั้นตอนการแจ้งเตือนไปก่อนได้)

## ตอนที่ 1: เตรียม Project และ Token (ประมาณ 5 นาที)

ก่อนจะเริ่มรับส่งข้อมูล เราต้องจัดสรรพื้นที่ทำงานใน Raina และออกกุญแจสำหรับให้อุปกรณ์ใช้ยืนยันตัวตนเสียก่อน

เริ่มต้นด้วยการคลิกไปที่เมนู **Projects** แล้วกดสร้างโปรเจกต์ใหม่ ตั้งชื่อว่า `Greenhouse Demo` เมื่อสร้างเสร็จแล้วให้คลิกเข้าไปยังโปรเจกต์นั้น จากนั้นเปิดเข้าไปที่แท็บ **Devices** แล้วกดปุ่ม **New token** เพื่อสร้างกุญแจใหม่ ตั้งชื่อกำกับไว้ว่า `demo-token` เมื่อระบบสร้างเสร็จแล้ว ให้คัดลอกค่า Token นั้นเก็บไว้ทันที

เมื่อได้ Token แล้ว ให้เปิดหน้าต่าง Terminal ขึ้นมา แล้วสั่งรันสคริปต์จำลองอุปกรณ์เพื่อเริ่มสตรีมข้อมูลอุณหภูมิและความชื้นจำลองผ่าน RLP เข้ามายังเซิร์ฟเวอร์:

```bash
PROJECT_TOKEN=<token> DEVICE_ID=demo_esp32 pnpm emulate
```

อย่าลืมแทนที่ `<token>` ด้วยค่าที่คุณเพิ่งคัดลอกมา เมื่อสคริปต์เริ่มทำงาน ให้สลับกลับมาดูที่หน้า Devices ในเบราว์เซอร์ คุณจะพบว่ามีอุปกรณ์ชื่อ `demo_esp32` ปรากฏขึ้นมาในรายการพร้อมกับแสดงสถานะว่ากำลังออนไลน์อยู่

## ตอนที่ 2: สร้าง Dashboard แสดงผลสด (ประมาณ 5 นาที)

เมื่อข้อมูลจากตัวจำลองเริ่มไหลเข้ามาในระบบแล้ว ขั้นต่อไปคือการสร้างหน้าจอเพื่อมอนิเตอร์ค่าเซ็นเซอร์เหล่านั้น

ให้เข้าไปที่แท็บ **Dashboards** ในโปรเจกต์เดิม แล้วกดสร้าง Dashboard ใหม่ ตั้งชื่อว่า `Greenhouse Overview` เมื่อเปิดเข้าสู่หน้าจอแก้ไข ให้ลาก Widget ชนิด **Value** มาวางลงบนกริด และกำหนดในแผงตั้งค่าด้านข้างให้ผูกเข้ากับตัวแปร `temperature` พร้อมใส่หน่วยกำกับเป็น `°C` จากนั้นลาก Widget ชนิด **Chart** มาวางเพิ่มเติม และเลือกผูกเข้ากับทั้งตัวแปร `temperature` และ `humidity` เพื่อดูแนวโน้มควบคู่กันไป

เมื่อกดบันทึกแล้วสลับไปยังมุมมองปกติ (View) คุณจะเห็นเส้นกราฟค่อย ๆ วาดและขยับต่อเนื่องทุก ๆ ประมาณ 3 วินาทีตามจังหวะที่ตัวจำลองส่งข้อมูลเข้ามา

## ตอนที่ 3: ตั้งระบบเตือน Telegram เมื่อร้อนเกิน 30°C (ประมาณ 10 นาที)

ขั้นตอนสุดท้ายคือการสร้างเวิร์กโฟลว์อัตโนมัติ เพื่อให้ระบบคอยเฝ้าระวังอุณหภูมิแทนเราและส่งข้อความเตือนเมื่ออากาศร้อนเกินไป

อันดับแรก ให้ไปที่ส่วน Integrations ในโปรเจกต์ กดสร้างช่องทางการเชื่อมต่อใหม่ เลือกบริการ **Telegram** กรอก Bot Token และ Chat ID ให้เรียบร้อย จากนั้นให้กดปุ่ม **Test** ทันทีเพื่อทดสอบว่าบอทสามารถส่งข้อความตัวอย่างเข้าห้องแชตได้จริง

เมื่อการเชื่อมต่อภายนอกทำงานได้แล้ว ให้เปิดไปที่แท็บ **Automations** แล้วกดสร้างเวิร์กโฟลว์ใหม่ ตั้งชื่อว่า `Heat alert` โดยเริ่มจากการวาง Trigger ชนิด **Variable** เลือกชื่อตัวแปรเป็น `temperature` กำหนดเงื่อนไขมากกว่า (`>`) และใส่ค่าเป้าหมายเป็น `30` จากนั้นลากบล็อก Action ชนิด **Integration** มาเชื่อมต่อต่อจาก Trigger เลือกช่องทาง Telegram ที่เราเพิ่งตั้งค่าไว้ และระบุข้อความแจ้งเตือน เช่น `"Greenhouse ร้อน {{value}}°C แล้ว"`

เมื่อเชื่อมบล็อกเรียบร้อย ให้กดบันทึกและเปิดสวิตช์เปิดใช้งาน (Enabled) ของเวิร์กโฟลว์ จากนั้นลองกดปุ่ม **Run** เพื่อทดสอบการทำงานดูหนึ่งรอบ

หลังจากเปิดใช้งานจริง ให้ปล่อยให้ตัวจำลองสุ่มส่งค่าอุณหภูมิที่สูงเกิน 30 องศาเข้ามา หรือหากไม่อยากรอ คุณสามารถเข้าไปแก้ไขค่าเป้าหมายใน Trigger ให้ต่ำลงมาชั่วคราวเพื่อเร่งการทดสอบได้ เมื่อเงื่อนไขตรงตามที่กำหนด คุณจะได้รับข้อความแจ้งเตือนเด้งเข้าแอป Telegram บนมือถือทันที และเมื่อเปิดดูในแท็บ Runs ของเวิร์กโฟลว์ ก็จะเห็นประวัติการทำงานขึ้นสถานะ `ok` อย่างสมบูรณ์

## สิ่งที่สามารถต่อยอดได้จากเวิร์กโฟลว์นี้

เมื่อเข้าใจการทำงานตั้งแต่ต้นจนจบแล้ว คุณสามารถนำระบบนี้ไปประยุกต์ใช้งานจริงได้อีกหลากหลายรูปแบบ

ตัวอย่างเช่น คุณสามารถเพิ่ม Widget ชนิด **Toggle** บนหน้า Dashboard เพื่อผูกเข้ากับตัวแปร `pump_relay` และเพิ่มบล็อก Action ชนิด **Set value** เข้าไปในเวิร์กโฟลว์เดิม เพื่อสั่งให้ปั๊มน้ำระบายความร้อนทำงานโดยอัตโนมัติพร้อม ๆ กับส่งข้อความแจ้งเตือนเข้า Telegram

หากต้องการนำไปใช้กับอุปกรณ์จริง คุณเพียงแค่นำโค้ดตัวอย่างใน [RLP และเฟิร์มแวร์](./rlp-and-firmware.md) ไปแฟลชลงบนบอร์ด ESP32 แล้วเปลี่ยนมาใช้ Token เดียวกัน อุปกรณ์จริงก็จะเริ่มทำงานแทนตัวจำลองทันที

นอกจากนี้ คุณยังสามารถเปิดโหมด Public access บนหน้า Dashboard เพื่อสร้างลิงก์แชร์ให้ทีมงานเปิดมอนิเตอร์บนสมาร์ตโฟนได้ตามคำแนะนำใน [Dashboards](./dashboards.md) และเมื่อพร้อมจะนำระบบขึ้นรันจริงบนเซิร์ฟเวอร์ถาวร สามารถอ่านคู่มือการติดตั้งและเปิดใช้งาน HTTPS ได้ใน [Deploy และดูแลระบบ](./operations.md)
