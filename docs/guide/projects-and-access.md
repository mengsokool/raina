# Projects และสิทธิ์ผู้ใช้

ระบบสิทธิ์ของ Raina ออกแบบมาเพื่อรองรับตั้งแต่การทดลองใช้งานส่วนตัว ไปจนถึงการที่ System Integrator นำระบบไปติดตั้งและส่งมอบให้กับลูกค้าหลายรายพร้อมกัน โดยแยกพื้นที่ทำงาน ข้อมูล และระดับการเข้าถึงของแต่ละคนออกจากกันอย่างชัดเจน

## สร้างและจัดการ Project

Project คือพื้นที่หลักสำหรับรวบรวมอุปกรณ์และทรัพยากรทั้งหมดที่เกี่ยวข้องกับงานชิ้นใดชิ้นหนึ่ง ผู้ใช้ในกลุ่มทีมดูแลระบบ ไม่ว่าจะเป็น Owner, Admin หรือ Staff สามารถสร้างโปรเจกต์ใหม่ได้จากหน้า **Projects** เมื่อสร้างเสร็จ แต่ละโปรเจกต์จะมี URL ประจำตัวในรูปแบบ `/p/<project-id>/...`

ภายในแต่ละโปรเจกต์จะมีเมนูย่อยสำหรับการทำงานครบถ้วน ทั้งหน้า Dashboards สำหรับสร้างหน้าจอมอนิเตอร์และแผงควบคุม, Devices สำหรับดูแลอุปกรณ์และออกรหัส Token, Variables สำหรับตรวจเช็กตัวแปรและดูประวัติย้อนหลัง, Automations สำหรับผูกเงื่อนไขสั่งงานอัตโนมัติ และ Users สำหรับจัดการสิทธิ์ของสมาชิก

สำหรับการลบโปรเจกต์ Raina จะใช้ระบบ Soft-delete โดยซ่อนโปรเจกต์นั้นออกจากรายการใช้งานทั่วไป เพื่อป้องกันความผิดพลาดและยังไม่ลบข้อมูลดิบทิ้งอย่างถาวรในทันที

## เชิญผู้ใช้เข้า Project

เมื่อคุณต้องการเปิดให้ลูกค้าหรือทีมงานเข้ามาใช้งานในโปรเจกต์ ให้เปิดเข้าไปที่โปรเจกต์นั้นแล้วเลือกเมนู **Users** จากนั้นกดเพิ่มผู้ใช้โดยระบุ Username และกำหนดรหัสผ่านที่มีความยาวอย่างน้อย 8 ตัวอักษร

ในขั้นตอนนี้ คุณสามารถเลือกได้ว่าจะให้ผู้ใช้มองเห็น Dashboard ทั้งหมดในโปรเจกต์ หรือจะระบุเฉพาะบาง Dashboard ที่ต้องการให้เข้าถึงผ่านตัวเลือก `dashboardIds` ผู้ใช้ที่เพิ่มเข้ามาด้วยวิธีนี้จะได้รับบทบาทระดับระบบเป็น **Client** โดยอัตโนมัติ ซึ่งจะทำให้พวกเขามองเห็นเฉพาะโปรเจกต์และหน้าที่คุณอนุญาตไว้เท่านั้น และจะไม่เห็นส่วนการตั้งค่าระบบของเซิร์ฟเวอร์

> กฎสำคัญของการจัดการสิทธิ์คือคุณสามารถมอบสิทธิ์หรือสร้างบทบาทให้ผู้อื่นได้สูงสุดไม่เกินระดับสิทธิ์ของตัวคุณเอง

## สิทธิ์ระดับ Dashboard

ในแต่ละหน้า Dashboard คุณสามารถควบคุมสิทธิ์ของผู้ใช้แต่ละคนแยกจากกันได้สองเรื่องหลัก เรื่องแรกคือสิทธิ์ในการมองเห็นหน้าจอนั้น และเรื่องที่สองคือสิทธิ์ในการกดส่งคำสั่งควบคุมอุปกรณ์ หรือ `canControl`

คุณสามารถนำความยืดหยุ่นนี้ไปปรับใช้กับกลุ่มผู้ใช้งานในโลกจริงได้หลากหลายรูปแบบ

| กลุ่มผู้ใช้งาน | แนวทางการตั้งค่า |
| :--- | :--- |
| ผู้ดูแลหน้างาน (Site Supervisor) | ให้สิทธิ์เห็นทุก Dashboard ในโปรเจกต์ และเปิด `canControl` ให้สามารถสั่งงานอุปกรณ์ได้ |
| ลูกค้าหรือผู้บริหาร (Client Executive) | เปิดให้เห็นเฉพาะ Dashboard สรุปภาพรวม และปิด `canControl` ให้อ่านค่าได้อย่างเดียว |
| ช่างเทคนิคประจำโซน (Field Technician) | เปิดให้เห็นเฉพาะ Dashboard ประจำโซนของตัวเอง และอนุญาตให้สั่งงานได้เฉพาะบางหน้า |

ทุกครั้งที่มีผู้ใช้กดปุ่ม เลื่อน Slider หรือส่งคำสั่งจาก Widget ควบคุมบนหน้าจอ Raina จะตรวจสอบสิทธิ์ `canControl` ก่อนเสมอ หากผู้ใช้นั้นไม่มีสิทธิ์สั่งงาน ระบบจะปฏิเสธคำสั่งและตอบกลับด้วยรหัสสถานะ `403 Forbidden`

## บทบาทระดับระบบ (System Roles)

หากมองในภาพรวมของทั้งเซิร์ฟเวอร์ Raina แบ่งบทบาทของผู้ใช้งานออกเป็น 4 ระดับตามความรับผิดชอบ

| บทบาท | เหมาะสำหรับ | ขอบเขตหน้าที่ |
| :--- | :--- | :--- |
| owner | ผู้ริเริ่มหรือเจ้าของระบบหลัก | จัดการได้ทุกอย่างในระบบ โดยไม่สามารถลบหรือลดสิทธิ์ของ Owner คนสุดท้ายของระบบได้ |
| admin | ผู้ดูแลระบบส่วนกลาง | จัดการ Staff, เข้าถึงและดูแลได้ทุก Project, จัดการ Token และอุปกรณ์ |
| staff | ทีมงานฝ่ายปฏิบัติการ | ดูแล Project ที่ได้รับมอบหมาย, แก้ไข Dashboard หรือ Automation และสั่งงานอุปกรณ์ |
| client | ลูกค้าหรือผู้ใช้งานปลายทาง | ใช้งานได้เฉพาะ Project และ Dashboard ที่ถูกเชิญเข้าไปเท่านั้น |

หากคุณต้องการเพิ่มหรือจัดการบัญชีในกลุ่มทีมดูแลระบบ เช่น Staff หรือ Admin ให้เข้าไปที่เมนู **Settings** แล้วเลือกส่วน **Staff**

## แนวทางการส่งมอบงานให้ลูกค้า

เมื่อต้องนำระบบไปส่งมอบให้ลูกค้าใช้งานจริง คุณสามารถวางโครงสร้างตามลำดับนี้เพื่อให้ดูแลรักษาง่ายในระยะยาว

เริ่มต้นด้วยการสร้างโปรเจกต์แยกหนึ่งอันต่อหนึ่งลูกค้าหรือแยกตามไซต์งานจริง เพื่อไม่ให้ข้อมูลของแต่ละพื้นที่ปะปนกัน จากนั้นสร้างบัญชีบทบาท Client ให้กับทีมงานของลูกค้าในโปรเจกต์นั้น โดยเลือกเปิดเฉพาะ Dashboard ที่จำเป็นต้องใช้งาน และเปิดสิทธิ์ `canControl` ให้เฉพาะหน้าที่ลูกค้าต้องสั่งงานจริง

ในกรณีที่ลูกค้าต้องการเพียงหน้าจอมอนิเตอร์สำหรับเปิดดูสถานะบนจอแสดงผลหน้าร้านหรือหน้างาน และไม่จำเป็นต้องมีบัญชีผู้ใช้งาน คุณสามารถเปลี่ยนโหมดการแชร์ Dashboard เป็นแบบ **Public access** แล้วส่งลิงก์ตรงให้เปิดดูได้ทันที ซึ่งคุณสามารถศึกษาเรื่องนี้เพิ่มเติมได้ใน [Dashboards](./dashboards.md)

นอกจากนี้ คุณยังสามารถอ่านขั้นตอนการเตรียมอุปกรณ์ต่อได้ที่ [Devices และ hardware token](./devices-and-tokens.md)
