# Deploy และดูแลระบบ

เอกสารส่วนนี้รวบรวมแนวทางการติดตั้ง Raina สำหรับใช้งานจริง การตั้งค่า HTTPS ร่วมกับ Reverse Proxy การสำรองข้อมูล และขั้นตอนการดูแลรักษาระบบให้อยู่ในสถานะพร้อมใช้งานอย่างต่อเนื่อง

## ติดตั้งด้วย Docker Compose

การติดตั้งและดูแลระบบผ่าน Docker Compose เป็นวิธีมาตรฐานที่แนะนำสำหรับการนำไปใช้งานจริง เนื่องจากระบบจะรวมเซอร์วิสที่จำเป็นทั้งหมดไว้ใน Stack เดียวกัน ทำให้ควบคุมสภาพแวดล้อมได้ง่าย

เริ่มต้นด้วยการดึงซอร์สโค้ดจาก Git คัดลอกไฟล์ตัวอย่างคอนฟิก และแก้ไขค่าตัวแปรสภาพแวดล้อมที่สำคัญ เช่น รหัสผ่านฐานข้อมูลและโดเมน จากนั้นจึงสั่งเริ่มทำงาน:

```bash
git clone https://github.com/mengsokool/raina.git
cd raina
cp .env.example .env
docker compose up -d
docker compose ps
```

ภายใน Stack นี้ Docker จะเริ่มทำงานคอนเทนเนอร์หลัก 5 ตัวพร้อมกัน ได้แก่ หน้าเว็บ Frontend บนพอร์ต 3000, API Server บนพอร์ต 3001, RLP Gateway สำหรับรับคอนเนกชันจากอุปกรณ์บนพอร์ต 9000, ฐานข้อมูล PostgreSQL พร้อมส่วนขยาย TimescaleDB สำหรับเก็บข้อมูล Time-Series บนพอร์ต 5432 และ Redis สำหรับจัดการแคชและคิวงานบนพอร์ต 6379

## ตั้งค่า HTTPS ด้วยโดเมนเดียว (Single Domain Setup)

Raina มาพร้อมกับคอนฟิกของ Caddy ที่ทำหน้าที่เป็น Reverse Proxy ในตัว ช่วยอำนวยความสะดวกในการขอและต่ออายุใบรับรองความปลอดภัย TLS จาก Let's Encrypt ให้อัตโนมัติโดยที่คุณไม่ต้องติดตั้ง Certbot แยกต่างหาก

ก่อนเริ่มใช้งาน ให้ชี้ DNS ของโดเมนที่คุณต้องการ เช่น `iot.yourdomain.com` มายังหมายเลข IP ของเซิร์ฟเวอร์ พร้อมทั้งเปิดพอร์ต 80 และ 443 สำหรับเว็บ รวมถึงพอร์ต 8883 สำหรับการเชื่อมต่อ RLP over TLS ที่ไฟร์วอลล์ของเครื่อง จากนั้นเปิดไฟล์ `.env` แล้วระบุโดเมนของคุณลงในตัวแปร `DOMAIN=iot.yourdomain.com` เมื่อพร้อมแล้วให้สั่งรันระบบร่วมกับโปรไฟล์ Proxy:

```bash
docker compose --profile proxy up -d
```

เมื่อ Caddy เริ่มทำงานและขอใบรับรองสำเร็จ การเข้าถึงทั้งหมดจะถูกจัดสรรอย่างเป็นระเบียบภายใต้โดเมนเดียว โดยหน้าเว็บหลักจะเปิดใช้งานได้ที่ `https://<domain>` ส่วนคำขอที่ส่งไปยัง REST API และการเชื่อมต่อ WebSocket จะวิ่งผ่านเส้นทาง `https://<domain>/v1/*` และคุณสามารถตรวจสอบความพร้อมของระบบได้ผ่านจุดตรวจสุขภาพที่ `https://<domain>/healthz`

## พอร์ตเครือข่ายและความปลอดภัย

เพื่อให้ระบบปลอดภัยและไม่ถูกโจมตีจากภายนอก คุณควรเปิดพอร์ตออกสู่อินเทอร์เน็ตเฉพาะพอร์ตที่จำเป็นเท่านั้น

| พอร์ต | หน้าที่การทำงาน | เปิดสู่เครือข่ายภายนอกหรือไม่ |
| :--- | :--- | :--- |
| 80 / 443 | ให้บริการเว็บและ API ผ่าน Caddy Reverse Proxy | **เปิด** |
| 8883 (TLS) | การเชื่อมต่อ RLP จากอุปกรณ์จริงสำหรับ Production | **เปิด** |
| 9000 (TCP) | การเชื่อมต่อ RLP แบบไม่เข้ารหัสสำหรับทดสอบในวงแลน | **เปิดเฉพาะภายใน LAN** |
| 3000 / 3001 | พอร์ตของ Frontend และ API โดยตรง | **ไม่ต้องเปิด** (เรียกผ่าน Caddy แทน) |
| 5432 / 6379 | พอร์ตฐานข้อมูล PostgreSQL และ Redis | **ห้ามเปิดออกอินเทอร์เน็ตเด็ดขาด** |

> โปรโตคอล RLP ที่อุปกรณ์ใช้เชื่อมต่อเข้ามาจะวิ่งตรงเข้าสู่ Gateway โดยไม่ผ่าน Caddy ดังนั้น ในการตั้งค่าฮาร์ดแวร์สำหรับ Production คุณต้องกำหนดให้อุปกรณ์ชี้มาที่โฮสต์และพอร์ต 8883 โดยตรง พร้อมทั้งติดตั้งใบรับรอง CA ที่ถูกต้องลงในเฟิร์มแวร์

## งานดูแลรักษาระบบประจำวัน

### การสำรองข้อมูล (Backup)

การสำรองข้อมูลเป็นหัวใจสำคัญของการดูแลระบบ คุณควรสำรองข้อมูลฐานข้อมูล PostgreSQL ร่วมกับไฟล์ `.env` ไว้อย่างสม่ำเสมอ โดยสามารถใช้คำสั่งนี้เพื่อดัมป์ข้อมูลและบีบอัดเป็นไฟล์ gzip:

```bash
docker compose exec -T postgres sh -c 'pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB"' \
  | gzip > raina-backup-$(date +%Y%m%d_%H%M%S).sql.gz
```

### การกู้คืนข้อมูล (Restore)

ในกรณีที่ต้องการกู้คืนข้อมูลจากไฟล์สำรอง ให้คลายการบีบอัดและส่งข้อมูลกลับเข้าสู่ฐานข้อมูลด้วยคำสั่ง:

```bash
gunzip < raina-backup-YYYYMMDD_HHMMSS.sql.gz \
  | docker compose exec -T postgres sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB"'
```

### การอัปเดตเวอร์ชันใหม่

เมื่อทีมพัฒนามีการปล่อยอัปเดตใหม่ของ Raina คุณสามารถดึงการเปลี่ยนแปลงล่าสุดและสั่งบิลด์คอนเทนเนอร์ใหม่ได้ทันที:

```bash
git pull
docker compose up -d --build
```

ระบบ Database Migration ภายในตัวเซิร์ฟเวอร์จะตรวจสอบและปรับปรุงโครงสร้างของฐานข้อมูลให้อัตโนมัติตอนที่คอนเทนเนอร์เริ่มสตาร์ต ทั้งนี้ แนะนำให้สำรองข้อมูลฐานข้อมูลเก็บไว้ก่อนทำการอัปเดตทุกครั้ง

### ตรวจสอบสุขภาพของระบบ (Diagnostics)

ผู้ดูแลระบบสามารถเข้ามาตรวจสอบปริมาณการใช้งานและสุขภาพของระบบได้จากหน้าเว็บ โดยเปิดไปที่เมนู **Settings** แล้วเลือกส่วน **Diagnostics** ซึ่งจะแสดงสถานะการเชื่อมต่อของ PostgreSQL, Redis ตลอดจนจำนวนโปรเจกต์ อุปกรณ์ และปริมาณข้อมูล Telemetry ทั้งหมด หรือหากต้องการดึงข้อมูลเชิงลึกไปใช้งานร่วมกับระบบมอนิเตอร์ภายนอก ก็สามารถเรียกผ่าน API ได้ที่ `GET /v1/admin/diagnostics`

## ตัวแปรสภาพแวดล้อมที่สำคัญใน `.env`

| ตัวแปร | ความหมายและผลกระทบ |
| :--- | :--- |
| `POSTGRES_PASSWORD` | รหัสผ่านสำหรับฐานข้อมูล (ต้องเปลี่ยนจากค่าเริ่มต้นเมื่อใช้งานจริง) |
| `SETUP_TOKEN` | รหัสผ่านพิเศษสำหรับลงทะเบียนบัญชี Owner คนแรก (หากปล่อยว่างไว้ ใครก็ตามที่เปิดหน้าเว็บคนแรกจะสามารถสมัครเป็น Owner ได้) |
| `TELEMETRY_RETENTION_DAYS` | ระยะเวลาจัดเก็บข้อมูลประวัติ Telemetry ในหน่วยวัน (ค่าเริ่มต้นคือ 30 วัน, หากใส่ `0` จะเก็บไว้ถาวร) |
| `AUTO_SEED` | กำหนดเป็น `true` หากต้องการให้ระบบลงข้อมูลตัวอย่างฟาร์มโรงเรือนในการเริ่มระบบครั้งแรก |
| `TYPESAFE_API_KEY` | คีย์ API สำหรับเปิดใช้งานฟีเจอร์พิมพ์ประโยคเพื่อสร้างกราฟ Automation (หากไม่ระบุ ยังคงสร้าง Automation ด้วยการลากบล็อกได้ตามปกติ) |
| `PUBLIC_RLP_HOST` / `PUBLIC_RLP_PORT` | โฮสต์และพอร์ตสาธารณะที่เซิร์ฟเวอร์จะแนะนำให้อุปกรณ์เชื่อมต่อเข้ามา |

สำหรับเครื่องที่มีทรัพยากรจำกัดมากหรือไม่สามารถใช้งาน Docker ได้ คุณสามารถศึกษาวิธีการติดตั้งและรันเซอร์วิสแบบ Native ผ่าน Systemd ได้ที่เอกสาร `deploy/native/README.md` ใน Repository นี้

หากพบปัญหาในการติดตั้งหรือเซอร์วิสไม่เริ่มทำงาน สามารถดูแนวทางแก้ไขได้ที่ [Troubleshooting](./troubleshooting.md)
