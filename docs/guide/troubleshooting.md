# Troubleshooting: แก้ปัญหาตามอาการ

เอกสารหน้านี้รวบรวมแนวทางการวิเคราะห์และแก้ไขปัญหาที่อาจพบได้ขณะติดตั้ง พัฒนา หรือส่งมอบระบบ Raina โดยแบ่งกลุ่มตามอาการที่เกิดขึ้นจริง เพื่อให้คุณตรวจสอบหาสาเหตุและแก้ไขได้ทันท่วงที

## อุปกรณ์เชื่อมต่อผ่าน RLP ไม่สำเร็จ

เมื่ออุปกรณ์ไมโครคอนโทรลเลอร์พยายามเชื่อมต่อผ่านโปรโตคอล RLP แต่หลุดทันที สาเหตุส่วนใหญ่มักเกิดจากการยืนยันตัวตนไม่ผ่าน หากค่า Token ไม่ถูกต้องหรือถูกเพิกถอนไปแล้ว RLP Gateway จะตอบกลับด้วยเฟรม Error และตัดการเชื่อมต่อทันที ในกรณีนี้ให้คุณเข้าไปที่หน้า Devices ในโปรเจกต์ ออก Token ใหม่ คัดลอกค่ามาให้ครบถ้วน แล้วอัปเดตลงในโค้ดของเฟิร์มแวร์อีกครั้ง

อีกสาเหตุที่พบบ่อยคือการระบุพอร์ตหรือโปรโตคอลผิดพลาด สำหรับการทดสอบในเครือข่ายแลน คุณต้องชี้ไปยังพอร์ต 9000 ซึ่งเป็น TCP ธรรมดา แต่ถ้าเป็นเซิร์ฟเวอร์จริงบน Production จะต้องชี้ไปยังพอร์ต 8883 ซึ่งเป็น TLS เสมอ พร้อมทั้งระบุใบรับรอง CA ให้ถูกต้อง และตรวจสอบว่าไฟร์วอลล์ของเซิร์ฟเวอร์เปิดให้พอร์ตดังกล่าวเข้าถึงได้ คุณสามารถตรวจดูพอร์ตที่ระบบประกาศใช้งานจริงได้ผ่าน `GET /v1/public/endpoints`

หากอุปกรณ์เชื่อมต่อได้แล้วแต่หลุดไปหลังจากนิ่งไปสักพัก มักเกิดจากเซิร์ฟเวอร์ตัดสายเมื่อไม่มีข้อมูลส่งเข้ามานานเกิน 90 วินาที ให้ตรวจดูว่าในฟังก์ชัน `loop()` ของเฟิร์มแวร์มีการเรียก `Raina.run()` อยู่ตลอดเวลาหรือไม่ และมีการส่ง PING หรือส่งข้อมูลเข้ามาอย่างสม่ำเสมอ นอกจากนี้ ขนาดของข้อมูลในแต่ละเฟรมจะต้องไม่เกิน 16 KB หากเซ็นเซอร์อ่านค่าได้ข้อมูลขนาดใหญ่ แนะนำให้แบ่งส่งเป็นหลายเฟรมแทน

## ส่งข้อมูล Telemetry แล้วค่าไม่ปรากฏในระบบ

หากคุณส่งข้อมูลผ่าน HTTP POST แล้วระบบตอบกลับด้วยรหัส `401 Unauthorized` แสดงว่าค่า Token ที่แนบมาใน Header `x-device-token` ไม่ถูกต้อง หรือหากได้รหัส `403 Forbidden` พร้อมข้อความ `Device ownership conflict` แสดงว่าชื่ออุปกรณ์ที่คุณส่งเข้ามา เคยถูกลงทะเบียนด้วย Token ตัวอื่นไปแล้ว ให้คุณเปลี่ยนชื่อ `deviceId` ให้ไม่ซ้ำกับอุปกรณ์เดิมในโปรเจกต์

หากคำขอผ่านไปด้วยรหัส 200 แต่ไม่มีตัวแปรใหม่เกิดขึ้น ให้ตรวจเช็กชื่อตัวแปรว่ามีอักขระพิเศษหรือเว้นวรรคหรือไม่ เพราะ Raina อนุญาตให้ใช้เฉพาะ `a-z A-Z 0-9 _ . -` และมีความยาวไม่เกิน 64 ตัวอักษร ตัวแปรที่ผิดรูปแบบจะถูกตัดทิ้งโดยไม่แจ้งเตือน รวมถึงการส่งตัวแปรเกิน 50 ตัวในครั้งเดียว ข้อมูลส่วนเกินก็จะถูกตัดออกเช่นกัน

ในกรณีที่ตัวแปรขึ้นบนหน้าจอ แต่ไม่สามารถนำไปพล็อตเป็นกราฟเส้นบน Widget Chart ได้ ให้ตรวจดูว่าข้อมูลที่ส่งเข้ามาเป็นตัวเลขจริงหรือไม่ เพราะระบบจะจัดเก็บประวัติ Time-Series สำหรับวาดกราฟเฉพาะข้อมูลที่เป็นตัวเลขเท่านั้น หากข้อมูลเป็นข้อความหรือค่าบูลีน ให้เปลี่ยนไปใช้ Widget ชนิด Value ในการแสดงผลแทน

นอกจากนี้ ให้ตรวจสอบค่าเวลา Timestamp ที่ส่งมาด้วย หากคุณแนบเวลาที่เก่าเกินกว่า 24 ชั่วโมง หรือเวลาล่วงหน้าเกินกว่า 10 นาทีเมื่อเทียบกับเซิร์ฟเวอร์ Raina จะบันทึกทับด้วยเวลาปัจจุบันของระบบแทนเพื่อรักษาความถูกต้องของฐานข้อมูล

## Dashboard ไม่อัปเดต หรือเปิดเข้าดูไม่ได้

หากเปิดลิงก์แชร์ของ Dashboard ไม่ขึ้น ให้ตรวจดูในเมนู Share ของ Dashboard หน้านั้นว่าไม่ได้อยู่ในสถานะ Paused หรือถูกเปลี่ยนโหมดเป็น Restricted ซึ่งผู้ใช้จำเป็นต้องล็อกอินเข้าสู่ระบบก่อน

สำหรับผู้ใช้ที่เป็นบทบาท Client หากเปิดเข้ามาแล้วไม่เห็นหน้า Dashboard ที่ต้องการ ให้ผู้ดูแลระบบตรวจสอบการตั้งค่าผู้ใช้ในโปรเจกต์ว่าได้เลือกติ๊กอนุญาตให้เข้าถึง Dashboard หน้านั้นแล้วหรือไม่

หากพบว่าหน้าเว็บค้างหรือข้อมูลไม่สตรีมเข้ามาแบบเรียลไทม์หลังจากอัปเดตระบบ ให้ลองทำ Hard Refresh บนเบราว์เซอร์ และตรวจเช็กว่าจุดตรวจสอบสุขภาพที่ `/healthz` ยังตอบกลับเป็นปกติหรือไม่ หากทุกอย่างปกติ ให้ตรวจสอบการตั้งค่าของ Reverse Proxy ว่าได้เปิดใช้งาน WebSocket Support แล้วหรือยัง แม้ Raina จะมีระบบสลับไปใช้ SSE อัตโนมัติ แต่พร็อกซีบางตัวอาจจำเป็นต้องเปิดการส่งผ่านส่วนหัวของ WebSocket ไว้อย่างชัดเจน

## กดสั่งอุปกรณ์จาก Dashboard แล้วอุปกรณ์ไม่ตอบสนอง

หากผู้ใช้กดสวิตช์หรือเลื่อนแถบควบคุมแล้วระบบปฏิเสธคำสั่งด้วยรหัส `403 Forbidden` แสดงว่าบัญชีของผู้ใช้ยังไม่ได้รับสิทธิ์ `canControl` ใน Dashboard หน้านั้น ให้ผู้ดูแลระบบเข้าไปเปิดสิทธิ์การควบคุมให้เรียบร้อย

หากคำขอผ่านไปได้แต่ตัวอุปกรณ์จริงไม่ขยับ ให้ตรวจเช็กว่าอุปกรณ์กำลังออนไลน์อยู่จริงในหน้า Devices หรือไม่ เพราะคำสั่งควบคุมผ่านโปรโตคอล RLP จะส่งไปยังอุปกรณ์ที่กำลังเปิด Socket ค้างอยู่ ณ ขณะนั้นเท่านั้น และให้ตรวจสอบการสะกดชื่อตัวแปรระหว่างในโค้ดเฟิร์มแวร์กับบนหน้าจอ Dashboard ว่าตรงกันทุกตัวอักษรหรือไม่ เพราะหากอุปกรณ์ไม่เคยลงทะเบียน Channel สำหรับชื่อตัวแปรนั้นไว้ตอนส่งคำทักทาย เซิร์ฟเวอร์จะไม่สามารถส่งคำสั่งลงไปได้

## Automation ไม่ทำงานตามเงื่อนไข

หากเวิร์กโฟลว์อัตโนมัติไม่ทำงานตามที่คาดหวัง ให้เริ่มตรวจสอบจากสวิตช์เปิดใช้งาน (Enabled) บนหน้า Automation ก่อนเสมอ เพราะเวิร์กโฟลว์ที่สร้างขึ้นใหม่อาจยังอยู่ในสถานะปิด

จากนั้นให้คลิกเข้าไปดูในแท็บ **Runs** หากไม่มีรอบการทำงานปรากฏขึ้นเลย แสดงว่าเงื่อนไขใน Trigger ยังไม่ถูกกระตุ้น ให้ตรวจสอบว่าชื่อตัวแปรที่ดักฟัง ตัวดำเนินการเปรียบเทียบ ค่าตัวเลขเป้าหมาย หรือการตั้งค่า Cooldown ถูกต้องหรือไม่ หาก Trigger เป็นการตั้งเวลา ให้ตรวจดูวันและเขตเวลา (Timezone) เพิ่มเติม

ในกรณีที่มีประวัติการทำงานบันทึกไว้แต่ขึ้นสถานะ `error` ให้คลิกดูรายละเอียดเพื่อหาว่าบล็อกไหนที่แสดงสีแดงเตือน หากเป็นบล็อกประเภท Integration ปัญหามักเกิดจากการตั้งค่าคอนฟิก ให้คุณเข้าไปที่หน้ารายการ Integration แล้วกดปุ่ม **Test** เพื่อทดสอบยิงข้อมูลดูโดยตรง เมื่อแก้ไขเสร็จแล้ว คุณสามารถกลับมาที่หน้ารายละเอียดของ Run แล้วกดปุ่ม **Retry** เพื่อให้ระบบทำงานต่อจากจุดที่ล้มเหลวได้ทันที

## Integration แจ้งเตือนไม่สำเร็จ

ทุกครั้งที่พบปัญหาการแจ้งเตือนไม่เข้าปลายทาง ให้ใช้ปุ่ม **Test** ในหน้าตั้งค่าของ Integration ตัวนั้นเสมอ เพื่อแยกแยะว่าปัญหาเกิดจากการเชื่อมต่อไปยังภายนอก หรือเกิดจากเงื่อนไขในตัวเวิร์กโฟลว์

สำหรับการเชื่อมต่อ Telegram ตรวจสอบว่าได้เชิญบอทเข้าสู่ห้องแชตหรือกลุ่มนั้นแล้ว และ Chat ID ถูกต้อง (สามารถใช้เป็นตัวเลข ID หรือ `@ชื่อกลุ่ม` ก็ได้)

สำหรับการส่งอีเมลผ่าน Resend ตรวจสอบว่าโดเมนของผู้ส่งได้รับการยืนยันสถานะในคอนโซลของ Resend เรียบร้อยแล้ว และ API Key จะต้องขึ้นต้นด้วย `re_` เสมอ

สำหรับช่องทาง Webhook ไม่ว่าจะเป็น Slack, Discord, Microsoft Teams หรือ HTTP Endpoint ทั่วไป ให้ตรวจสอบว่าคัดลอก URL มาอย่างครบถ้วนโดยไม่มีช่องว่างเกินมา และตรวจสอบ Log ของฝั่งเซิร์ฟเวอร์ปลายทางว่าได้รับคำขอส่งเข้ามาหรือไม่ ส่วนการเชื่อมต่อกับ PagerDuty ให้ตรวจเช็กว่า Routing Key มีความยาวครบ 32 ตัวอักษรอย่างถูกต้อง

## ปัญหาการเข้าใช้งานและบัญชีผู้ใช้

เมื่อเปิดหน้าเว็บ Raina ขึ้นมาเป็นครั้งแรกแล้วไม่พบหน้าสร้างบัญชี Owner แสดงว่าระบบมีบัญชีผู้ดูแลถูกสร้างไว้ก่อนหน้านี้แล้ว ให้สลับไปที่หน้าเข้าสู่ระบบแทน ในสภาพแวดล้อมใช้งานจริง แนะนำให้กำหนดตัวแปร `SETUP_TOKEN` ในไฟล์ `.env` ไว้เสมอ เพื่อป้องกันไม่ให้บุคคลภายนอกมาชิงสมัครบัญชีผู้ดูแลคนแรก

หากคุณพิมพ์รหัสผ่านผิดติดต่อกันเกิน 10 ครั้งภายใน 1 นาที ระบบจะระงับการเข้าสู่ระบบชั่วคราวเพื่อป้องกันการสุ่มรหัสผ่าน ให้รอประมาณ 1 นาทีแล้วจึงลองเข้าสู่ระบบใหม่อีกครั้ง และสำหรับคุกกี้เซสชันของผู้ใช้จะมีอายุการใช้งาน 30 วัน เมื่อครบกำหนด ระบบจะขอให้คุณล็อกอินใหม่อีกครั้ง

## คอนเทนเนอร์หรือเซอร์วิสเริ่มทำงานไม่ขึ้น

หากรันระบบผ่าน Docker Compose แล้วพบว่าบางเซอร์วิสไม่ทำงาน ให้ตรวจสอบสถานะและดูข้อความแจ้งเตือนด้วยคำสั่งต่อไปนี้:

```bash
docker compose ps
docker compose logs -f server rlp-gateway web
curl -fsS http://127.0.0.1:3001/healthz
```

เซอร์วิส `server` ถูกตั้งค่าให้รอจนกว่าฐานข้อมูล `postgres` และ `redis` จะเข้าสู่สถานะ Healthy เสียก่อน หากฐานข้อมูลยังเริ่มทำงานไม่เสร็จ ให้รอสักครู่และตรวจเช็ก Log ของคอนเทนเนอร์ฐานข้อมูลโดยตรง

นอกจากนี้ ให้ตรวจสอบว่าบนเซิร์ฟเวอร์ไม่มีโปรแกรมอื่นใช้งานพอร์ต 3000, 3001 หรือ 9000 ชนกัน และหากระบบเกิดปัญหาหลังจากการอัปเดตโค้ด ให้ดึงโค้ดเวอร์ชันล่าสุดด้วย `git pull` แล้วสั่ง `docker compose up -d --build` ใหม่อีกรอบ ทั้งนี้ อย่าลืมสำรองข้อมูลฐานข้อมูลเก็บไว้ก่อนเสมอตามขั้นตอนใน [Deploy และดูแลระบบ](./operations.md)

คุณสามารถกลับไปเริ่มต้นศึกษาภาพรวมของระบบทั้งหมดได้ที่ [กลับหน้าคู่มือหลัก](./README.md)
